## 1. Headline

v0.10.0 is a **subsystem-fundament** milestone, centred on **Events**. It lands the Events ordering/OCC
boundary (`EventStreamAppender` append-with-expected-version + per-stream total ordering, proven across
**two** bindings), the Event-Payload Codec SPI, and a binding-agnostic `topic` sink for the SDK — the
three pieces the generated-tooling event story was blocked on. Alongside, **Security** gains a dedicated
`IdentityProvider` SPI with an OIDC+JWKS first driver (consuming the v0.9 JWKS-rotation seam), and **HTTP**
gains three consumability pieces: SSE server-push streaming (ADR-043, pulled earlier than its planned
v0.12), a client-side retry policy (ADR-045), and generated-app boot-path routing (`{id}` path params +
request-decoder request-scope). The milestone also **decides** — but does not yet implement — the
shared-world isolation tier (RFC-2026-07-02, ACCEPTED). No "breaking change" framing: there are no
external SPI consumers pre-1.0, and every SPI change this milestone is additive.

## 2. What landed (by stream)

### 2.1 Security — IdentityProvider SPI + Community OIDC driver — ADR-040 (Sprint 1)
A dedicated identity SPI (`eu.exeris.kernel.spi.security`) split out from `SecurityProvider`, with an
OIDC+JWKS first driver and parsed identity propagated outbound. Builds directly on the v0.9 JWKS
key-rotation seam. Keycloak Testcontainers IT. RFC-2026-06-08 → ADR-040 (#218).

### 2.2 HTTP server-push / SSE streaming — ADR-043 (#214)
SSE-first server push over a sibling `HttpStreamExchange` (the respond-once invariant is preserved — a
stream exchange is a distinct shape, not a second response on the unary path). Core SSE framing +
Community transport binding + `AbstractHttpStreamExchangeTck`. WebSocket remains deferred. Brought
forward from the originally-planned v0.12.

### 2.3 HTTP client retry — HttpRetryPolicy SPI — ADR-045 (#220)
`HttpRetryPolicy` SPI + a `KernelWebClient` retry loop + a Community default policy, closing the
client-side half of the outbound-HTTP story (the body-codec/retry design was RFC-only in v0.9).

### 2.4 Events — Event-Payload Codec SPI — ADR-046 (#222, #223)
`EventPayloadCodec` + a codec registry + a Community JSON driver + TCK (PR-A), then the bootstrap binding
and an encode-failure JFR event (PR-A.1). Decouples event payload (de)serialization from the binding so a
type's wire form is a resolved codec concern, not hard-wired.

### 2.5 Events — log-ordering & OCC boundary — ADR-049 (#225–#228)
The subsystem's ordering fundament, landed as a decision + three implementation slices:
- **Decision** (#225): `EventStreamAppender` (Events SPI) owns append-with-expected-version + per-`StreamId`
  total ordering; `FlowSnapshot` CAS stays Persistence-owned; the transient `EventBus` stays unordered by
  design (topic-blind, ADR-049 H2).
- **SPI + ordering** (#226): `EventStreamAppender.append(...expectedVersion...)` + the per-stream ordering
  contract.
- **Community JDBC/Postgres binding** (#227) and **Community Kafka binding** (#228) — the **≥2-binding
  gate** that turns an SPI contract from "asserted" into "proven on the wire" is now closed.

### 2.6 Events — binding-agnostic `topic` — ADR-050 (#229)
An optional `EventTypeSpec.topic` (per-**type**, alongside `name` — off the hot path, not on the
primitive `EventDescriptor`) is the kernel sink for the SDK `@DomainEvent.topic` attribute. The Kafka
binding resolves `effectiveTopic = topicFor(hasTopic() ? topic() : name())` on **both** publish and
subscribe, so a topic-overridden type is never stranded. A blank `topic` normalizes to `null` in the
canonical constructor so null-vs-blank is one identity (no spurious registry conflict). The in-memory
`EventBus` treats `topic` as advisory (topic-blind by design).

### 2.7 HTTP — generated-app boot-path reachability — W7 (#224)
`{id}` path-parameter routing + a request-decoder bound to request-scope, closing the gap where a
generated app's parameterized routes and per-request decode were unreachable on the boot path.

### 2.8 Decisions (RFC track — no SPI commit this milestone)
- **Shared-scope isolation tier** — `RFC-2026-07-02` (**ACCEPTED**). The shared-world tier is ruled an
  *orthogonal row-visibility dimension* (`sharedScopeKey` + a `SHARED_WORLD` visibility mode) that composes
  with the physical `IsolationStrategy`, **not** a fourth mutually-exclusive strategy value. Write model:
  read-widen + owner-scoped write. Kernel-neutral naming — the game-domain "Universe" stays the SDK-facing
  name (tooling records the mapping); the kernel SPI never carries the metaphor. Fail-closed inheritance
  from ADR-012 §4a is unchanged (absent → tenant-private; declared-but-unenforceable → terminal deny). The
  SPI carrier + RLS mode land later as an in-place ADR-012 amendment. Unblocks the downstream SDK companion
  `RFC-2026-06-24`.
- **WebClient service addressing** — `RFC-2026-06-29` relocated from `exeris-docs` into the kernel repo,
  per the owning-repo-holds-the-SPI-RFC convention (#230).

## 3. SPI surface delta
- **Added:** `eu.exeris.kernel.spi.security` `IdentityProvider` (ADR-040); `HttpStreamExchange` streaming
  SPI (ADR-043); `HttpRetryPolicy` (ADR-045); `EventPayloadCodec` + registry (ADR-046);
  `EventStreamAppender` append-with-expected-version + per-stream ordering (ADR-049); optional
  `EventTypeSpec.topic` + `hasTopic()` + 3-arg factories (ADR-050); HTTP path-parameter routing +
  request-scoped decoder (W7).
- **Removed:** none.
- **Decision-only (no SPI this milestone):** shared-scope isolation tier (RFC-2026-07-02) — carrier lands
  as a later ADR-012 amendment.

## 4. Telemetry / JFR delta
New events include the ADR-046 event-payload **encode-failure** JFR event and the Kafka topic-resolution
diagnostic path (ADR-050). All single-phase commit, secret-safe payloads.

## 5. Quality and gate posture
- **≥2-binding gate closed** for the Events ordering/OCC contract (Community JDBC/Postgres + Kafka).
- Kafka topic-override delivery proven end-to-end via Testcontainers (`AbstractKafkaEventEngineTck`).
- TCK expansion across the new Events surfaces (registry topic round-trip + identity, ordering/OCC,
  codec) and the identity + streaming SPIs.

## 6. Migration / upgrade notes (v0.9.0 → v0.10.0)
- **Additive at the SPI level** — no removals; existing consumers are unaffected.
- **Events `topic`** — purely optional. A type registered via the 2-arg `EventTypeSpec` factories behaves
  exactly as before (name-derived routing). Populate `topic` only to override; a blank value is normalized
  to "no override".
- **Provider priority** — open-core priority is now Community=`0` / Enterprise=`100` (was mixed
  `100/200` in stale text); relevant only if you hand-tune provider ordering (#217).
- **HTTP streaming** — SSE responses use the sibling `HttpStreamExchange`; the unary respond-once path is
  unchanged.

  `exeris-sdk` — `@DomainEvent.topic` Javadoc stance + move `RFC-2026-06-24` off DRAFT.
- **v0.11 fundament:** `BlobStorageProvider`, `JobScheduler`, `CacheProvider` RFC.
- **1.0-GA horizon:** Platform Baseline / preview-clean, supply-chain + SPI binary-compat gate, Unified
  Clock seam.
