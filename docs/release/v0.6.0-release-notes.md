# Exeris Kernel v0.6.0 — Release Notes

> Status: **reconstructed**. v0.6.0 shipped on 2026-05-01 without release notes and predates the
> first `CHANGELOG.md` entry (which starts at 0.7.0). This document was written after the fact, on
> 2026-08-05, from the git record between `v0.5.0` and `v0.6.0` plus the machine-generated SPI diff.
> It is deliberately narrower than a contemporaneous release note: it states what can be proven from
> the repository, and does not reconstruct intent that was never written down.
>
> Companion docs: [`spi-api-history.md`](./spi-api-history.md) §1 (generated SPI diff);
> [`upgrade-0.5-to-0.10.md`](./upgrade-0.5-to-0.10.md) §1 (migration).

## 1. Why this document exists

v0.6.0 carries the **only** removal of `stable`-surface SPI types in the project's history before the
stability declaration existed, and it was the one release with no notes. That combination made a
0.5.x → later upgrade undocumented at exactly the point where it was hardest. This file closes that
gap retroactively.

The release itself was integrated as a single squash merge (`5c56395d`, PR #82,
*"Release 0.6.0: Flow recovery, TCK closure, transport/HTTP refactor"*).

## 2. SPI changes — the part that affects consumers

Three types were removed outright, along with the three members that returned them:

| Removed | Module | Replacement |
|---|---|---|
| `spi.persistence.DatabaseDialect` (+ nested `ImmutableDatabaseDialect`) | SPI | none — dialect selection became a driver-internal concern |
| `spi.persistence.PersistenceEngineCapabilities` | SPI | none — use `PersistenceEngine.healthCheckDetailed()` and `stats()` |
| `spi.transport.TransportEngineCapabilities` | SPI | discrete accessors: `TransportEngine.mode()`, `engineName()`, `stats()` |
| `PersistenceEngine.capabilities()` | SPI | as above |
| `PersistenceProvider.dialect(PersistenceConfig)` | SPI | as above |
| `TransportEngine.capabilities()` | SPI | as above |

`DatabaseDialect` enumerated concrete engines and parsed JDBC URLs inside the contract module — a
driver detail living in SPI, which is what The Wall exists to prevent. The capability records went
in the same pass: a frozen descriptor cannot describe a provider set discovered at runtime.

No other public SPI surface was removed or reshaped. Full generated evidence:
[`spi-api-history.md`](./spi-api-history.md) §1.

## 3. What else landed

Reconstructed from the squash-merge body; grouped, not exhaustive.

**Flow — recovery and shutdown.** `CoreFlowRuntime` gained snapshot-based recovery for parked flows,
registration of restored parked instances, and lifecycle-counter handling across engine restart
(including stale-lifecycle handling and snapshot finalization during shutdown). A new
`FlowEngineShutdownEvent` emits final runtime statistics after closure. Parked-flow lookup suppresses
repeated snapshot-store probes after a miss.

**Transport / HTTP.** `NativeTcpCarrier` and `NativeTcpStream` were reworked for reactor request
handling and queue management, with inbound/outbound consumer management tightened for thread
safety. `CoreSyscallLoader` exposes cross-platform POSIX / Winsock socket symbol loading;
`SocketChannelFdAccess` / `SocketChannelFdReflectionResolver` reworked for FD access and backend
selection; `SyscallErrno` improved for Windows. `CommunityHttpSubsystem` / `CommunityHttpExchange`
response handling and error management reworked; `ProcessingState` gained `AggregateExpansion` for
buffer management, with unit tests covering allocation failure.

**Events.** `CommunityEventProvider` implemented. `PaqsHandlerFailure` is emitted on handler failure,
with stream cleanup improved.

**TCK.** Contract tests added across Community and Core; `StorageContextBridge` gained a null-principal
check; TCK tests moved to `ConfigProvider.KernelSettings`.

**Build / CI.** JFR reporting via GitHub Actions, JMH results publishing, a published-version checker,
and simplified GitHub Packages publishing. TLS benchmark setup gained dynamic certificate resolution.

## 4. Pre-1.0 stance at the time

v0.6.0 predates [`../stability-matrix.md`](../stability-matrix.md), which was first published in
v0.9.0. There was no maturity declaration in force when these types were removed, so the removals
were not a violation of a published contract — but they were also not announced, which is the gap
this document and the CI gate introduced in v0.11 together close.
