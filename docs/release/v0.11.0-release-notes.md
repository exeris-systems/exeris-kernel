## Compatibility: `spi.flow` — `FlowSnapshot` gains three record components

`eu.exeris.kernel.spi.flow` is declared **stable since 0.5.0**. v0.11 adds three components to the
`FlowSnapshot` record — `currentStepName`
([ADR-062](../adr/ADR-062-flow-step-identity-on-resume.md)), `definitionVersion` and
`compensationStepNames`
([ADR-064](../adr/ADR-064-flow-definition-versioning-and-in-flight-migration.md), the latter by its
amendment A5) — taking the canonical constructor from eleven parameters to fourteen. Each records an
identity the runtime previously inferred from a position: which step the saga parked at, which
definition version it parked under, and which steps its compensation stack would roll back.

**What is preserved.** The 0.10.0 constructor descriptor is restored as an overload. Code compiled
against 0.10.0 continues to construct snapshots, at source and at binary level. All three new
components default to their fail-closed sentinels (`Optional.empty()`, `FlowSnapshot.VERSION_ABSENT`
and an empty identity array), so the bridge grants compilation and **not** a bypass: a snapshot built
through it is refused on resume by exactly the guards those decisions added.
`AbstractFlowDefinitionVersioningTck$StabilityCompatibility` asserts both halves — that it compiles,
and that it still refuses — because a bridge satisfying only the first would quietly undo all three.

Because 0.11 is unreleased, the intermediate twelve- and thirteen-parameter descriptors never shipped.
One overload therefore covers the whole milestone; no second bridge is owed, and none is added.
`FlowMigrationState` gains a component in the same amendment and deliberately gets **no** overload —
it is `@since 0.11.0`, so nothing compiled against a released artifact constructs it, and a bridge
defaulting the identities to absent would hand a migration transform the one input the new guard
exists to refuse.

**What is not preserved, and cannot be.** Adding a component changes the record's *component list*.
Record deconstruction patterns (`case FlowSnapshot(var a, var b, …)`) and reflection over
`RecordComponent[]` observe the new shape; no overload can hide that. This is irreducible for a
record. The alternative was to not record the parked step's identity, the definition version and the
compensation stack's identities at all — which is the data-corruption class these decisions exist to
close, so the trade was made knowingly rather than by omission.

**Where a diff does and does not see this.** A source-level diff of the record declaration shows the
component list changing. A *binary* compatibility diff does not flag it at all — because nothing was
removed: the 0.10.0 constructor descriptor is still present and the new components only add accessors.
That is the bridge doing more than granting compilation, and it is worth stating plainly because the
opposite was assumed while this was being written: the reflective and pattern-matching exposure above
is real, and it is exactly the kind of change an automated binary gate is silent about. Recording it
while the milestone is still open is the whole point of declaring a surface stable.

**What the third component changes at runtime.** A parked saga's compensation stack was stored as bare
plan positions, so a redeploy or a migration transform could leave it addressing steps the saga never
ran. Resume now refuses that (`COMPENSATION_STACK_IDENTITY_MISMATCH`), and refuses a live stack that
carries no identities at all (`COMPENSATION_STACK_IDENTITY_ABSENT`) rather than trusting it by
position. Both leave the row intact and recoverable, like every other resume refusal. Durable stores
gain a nullable `compensation_step_names` column (`V0.11.2`); a row written before it existed reads
back as no identities recorded, which is the absent case above.

## Compatibility: `spi.flow` — `FlowExecutionPlanFactory.registerMigration`

ADR-064 adds `registerMigration(String, int, FlowDefinitionMigration)` to `FlowExecutionPlanFactory`.
It carries a **default that refuses** with `UnsupportedOperationException`, so an implementor written
against 0.10.x still compiles. The default does not fabricate migration support: a factory that cannot
chain versions says so, rather than accepting a transform it will never apply.

Binary compatibility would not have required the default — adding a method to an interface links fine
until it is invoked, so a binary gate is silent here too. Source compatibility does require it, and the
same rule produced `FlowSnapshotStore.listParked()`'s default in 0.7.0. That one returns an empty list
rather than refusing, and the difference is deliberate: an empty parked list is a truthful degenerate
answer, while accepting a migration transform that will never be applied is not.

## Compatibility: `spi.security` — `ImmutableStorageContext` gains a component

`eu.exeris.kernel.spi.security` is declared **preview**, where breaking changes are permitted before
promotion — and per the semver policy they are called out here rather than left to be discovered.

`ImmutableStorageContext` gains a sixth component, `sharedScopeKey` (ADR-012 shared-scope amendment).
Unlike `FlowSnapshot` above, the previous five-argument constructor was **not** retained, so this is a
binary-incompatible change: code compiled against 0.10.x that constructs the record directly must be
recompiled. Use the `withSharedScope()` composer rather than the canonical constructor where the axis
is not being set — the shared-scope key is orthogonal to the isolation strategy, and composing keeps
call sites insulated from further components on this carrier while it remains `preview`.

## Benchmarking: v0.11 moves the HTTP/1.1 per-request hot path

Numbers measured on 0.10.x and on 0.11.0 are **not comparable without annotation**, and this is stated
before a measurement campaign rather than after one.

`DrainCoordinator` did not exist when the pre-0.11 figures were taken. It adds two atomic
read-modify-writes on a shared per-engine counter to the H1 keep-alive loop — `markIdle()` when the
connection parks on the next request, `markBusy()` when one arrives — so the cost lands **per request**,
not per connection, and on one cache line shared by every stream the engine is serving. Whether that is
visible above a given harness's noise floor is a question for a measurement, not for release notes; that
it changes the path is not.

The concurrency shape settled during this milestone and the final form is what any campaign must
measure. Both operations are unconditional `getAndAdd` — the seal that closes the drain's commit window
is expressed as a **negative range** rather than an exact sentinel value precisely so the hot path does
not need a compare-and-set retry loop, which is the form that degrades under contention. An interim
version during review did use CAS loops; it is not what ships.

Treat 0.11.0 as a fence in the benchmark record, in the same way individual commits that moved this path
have been annotated before. A figure carried across it without a note will read as an unexplained
regression to whoever compares them next — including the person who took them.
