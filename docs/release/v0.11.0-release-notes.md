## Compatibility: `spi.flow` — `FlowSnapshot` gains two record components

`eu.exeris.kernel.spi.flow` is declared **stable since 0.5.0**. v0.11 adds two components to the
`FlowSnapshot` record — `currentStepName`
([ADR-062](../adr/ADR-062-flow-step-identity-on-resume.md)) and `definitionVersion`
([ADR-064](../adr/ADR-064-flow-definition-versioning-and-in-flight-migration.md)) — taking the
canonical constructor from eleven parameters to thirteen.

**What is preserved.** The 0.10.0 constructor descriptor is restored as an overload. Code compiled
against 0.10.0 continues to construct snapshots, at source and at binary level. Both new components
default to their fail-closed sentinels (`Optional.empty()` and `FlowSnapshot.VERSION_ABSENT`), so the
bridge grants compilation and **not** a bypass: a snapshot built through it is refused on resume by
exactly the guards those two ADRs added. `AbstractFlowDefinitionVersioningTck$StabilityCompatibility`
asserts both halves — that it compiles, and that it still refuses — because a bridge satisfying only
the first would quietly undo both decisions.

**What is not preserved, and cannot be.** Adding a component changes the record's *component list*.
Record deconstruction patterns (`case FlowSnapshot(var a, var b, …)`) and reflection over
`RecordComponent[]` observe the new shape; no overload can hide that. This is irreducible for a
record. The alternative was to not record the parked step's identity and the definition version at
all — which is the data-corruption class both ADRs exist to close, so the trade was made knowingly
rather than by omission.

**Where a diff does and does not see this.** A source-level diff of the record declaration shows the
component list changing. A *binary* compatibility diff does not flag it at all — because nothing was
removed: the 0.10.0 constructor descriptor is still present and the new components only add accessors.
That is the bridge doing more than granting compilation, and it is worth stating plainly because the
opposite was assumed while this was being written: the reflective and pattern-matching exposure above
is real, and it is exactly the kind of change an automated binary gate is silent about. Recording it
while the milestone is still open is the whole point of declaring a surface stable.

## Compatibility: `spi.flow` — `FlowExecutionPlanFactory.registerMigration`

ADR-064 adds `registerMigration(String, int, FlowDefinitionMigration)` to `FlowExecutionPlanFactory`.
It carries a **default that refuses** with `UnsupportedOperationException`, so an implementor written
against 0.10.x still compiles. The default does not fabricate migration support: a factory that cannot
chain versions says so, rather than accepting a transform it will never apply.

Binary compatibility would not have required the default — adding a method to an interface links fine
until it is invoked, so a binary gate is silent here too. Source compatibility does require it, and the
same rule produced `FlowSnapshotStore.listParked()`'s default in 0.7.0. That one returns an empty list
rather than refusing, and the difference is deliberate: an empty parked list is a truthful degenerate
answer, while accepting a migration transform that will never be applied is not.

## Compatibility: `spi.security` — `ImmutableStorageContext` gains a component

`eu.exeris.kernel.spi.security` is declared **preview**, where breaking changes are permitted before
promotion — and per the semver policy they are called out here rather than left to be discovered.

`ImmutableStorageContext` gains a sixth component, `sharedScopeKey` (ADR-012 shared-scope amendment).
Unlike `FlowSnapshot` above, the previous five-argument constructor was **not** retained, so this is a
binary-incompatible change: code compiled against 0.10.x that constructs the record directly must be
recompiled. Use the `withSharedScope()` composer rather than the canonical constructor where the axis
is not being set — the shared-scope key is orthogonal to the isolation strategy, and composing keeps
call sites insulated from further components on this carrier while it remains `preview`.
