# ADR-030 — Phase 4C Scope: Spring-Side Seam for Kernel Graph SPI (link stub)

**Authoritative copy:** [`exeris-spring-runtime/docs/adr/ADR-030-phase-4c-spring-side-seam-for-kernel-graph-spi.md`](https://github.com/exeris-systems/exeris-spring-runtime/blob/main/docs/adr/ADR-030-phase-4c-spring-side-seam-for-kernel-graph-spi.md)

ADR-030 is owned by `exeris-spring-runtime` and ships **no kernel change** — its own scope line says
so: *"introduces `exeris-spring-runtime-graph` module; binds `KernelProviders.GRAPH_ENGINE` and
exposes `GraphSession` to Spring beans; no kernel SPI changes"*.

**This stub exists because its sibling already claimed it should.**
[ADR-063's stub](./ADR-063.link.md) describes ADR-030 as *"likewise a spring-runtime decision the
kernel keeps awareness of"* and then records that neither had a kernel-side file. One of the two
subsequently got one. That asymmetry was the drift: either both warrant awareness or the sentence
naming them as the same shape was wrong, and reading ADR-030 says it is the same shape.

## What it consumes here

`KernelProviders.GRAPH_ENGINE` — the Spring module binds the kernel's graph engine into a Spring
bean and hands `GraphSession` to application code. Enforcement, session lifecycle and the
driver-selection rules stay entirely kernel-side; the Spring seam is a binding, not a second engine.

## Why a kernel reader should care

The consequence is the same one ADR-063 carries for the route-policy surface: **a change to the graph
SPI's session or lifecycle semantics is inherited by a Spring-hosted deployment that never sees this
repository.** In particular —

- `GraphSession`'s lifecycle: the Spring module hands the session to bean code, so any change to when
  a session may be used, or to what closing one does, reaches applications through a seam this
  repository does not own.
- `KernelProviders.GRAPH_ENGINE`'s binding lifecycle: bound once at bootstrap here, and the Spring
  binding assumes that shape.
- Graph driver selection: `GraphBootstrap` ranks providers by priority. A Spring-hosted deployment
  gets whatever this repository selects, with no Spring-side override.

## When to consult ADR-030

- Any change to `GraphSession` semantics or to the `GRAPH_ENGINE` slot's lifecycle.
- Any change to graph driver selection or to `GraphConfig`'s shape.
- Work on the multi-hop traversal gap the ROADMAP tracks: a Spring-side consumer composing hops
  client-side is the shape that gap is about.
