# ADR-025 — AI Agent Bridge / MCP Server for Ecosystem Introspection (link stub)

**Authoritative copy:** [`../../../exeris-ai-bridge/docs/adr/ADR-025-ai-agent-bridge.md`](../../../exeris-ai-bridge/docs/adr/ADR-025-ai-agent-bridge.md)

ADR-025 is a **cross-repo** decision owned by `exeris-ai-bridge`. It binds this kernel repository because the `kernel:*` tool family in the bridge consumes a new read-only diagnostic SPI (`KernelDiagnostics`) that lives in `exeris-kernel-spi`, with provider implementations in Community.

## Why this stub exists

The agent-bridge surface lives in a separate TypeScript repo, but the contract it consumes is a kernel SPI. Kernel reviewers reading `docs/adr/` should find ADR-025 without needing to know where the authoritative copy lives.

## When to consult ADR-025 from kernel

- Any PR that adds, changes, or removes types in `eu.exeris.kernel.spi.diagnostics.*` — verify alignment with ADR-025 §Concrete obligations item 4 (read-only, process-boundary-safe).
- Any PR that adds a community provider for `KernelDiagnostics` — verify the surface does NOT expose mutation paths.
- Any proposal to link an AI-tooling artefact directly into the kernel classpath — STOP and re-read ADR-025 §Concrete obligations item 4 + ADR-006 (The Wall). The bridge stays out-of-process, in TypeScript, by design.
- Any RFC that proposes extending kernel introspection beyond the read-only set — the RFC must reference ADR-025 and explicitly justify any new surface in light of it.

## Engineering status

ADR-025 is **ACCEPTED** (2026-05-15). The `KernelDiagnostics` SPI itself is blocked on a follow-up RFC inside `exeris-kernel/docs/rfc/` per ADR-025 §Engineering Protocol item 2 — until that RFC lands, no `kernel:*` tool ships in the bridge.
