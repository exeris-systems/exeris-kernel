# ADR-006 — Spring-Free Kernel Boundary ("The Wall") (link stub)

**Authoritative copy:** `exeris-spring-runtime/docs/adr/ADR-006 Spring-Free Kernel Boundary.md`

ADR-006 is a **cross-repo** decision owned by `exeris-spring-runtime`. It binds this kernel repository: `exeris-kernel-spi`, `exeris-kernel-core`, `exeris-kernel-community`, and `exeris-kernel-enterprise` MUST contain zero `org.springframework.*` imports and MUST NOT assume Spring at runtime.

## Why this stub exists

The Wall is articulated and enforced from the spring-runtime side (where the boundary is bridged), but it binds the kernel side equally. This stub exists so kernel reviewers reading `docs/adr/` find the rule without needing to know which repo owns the authoritative copy.

## When to consult ADR-006 from kernel

- Any PR that adds a dependency to `exeris-kernel-*` POMs — verify no transitive Spring import.
- Any PR that touches `eu.exeris.kernel.spi.*` or `eu.exeris.kernel.core.*` — verify no Spring annotations, types, or lifecycle hooks leak in.
- Any change to `KernelBootstrap` — verify the kernel can boot with zero Spring on the classpath.
- Any change to `WallIntegrityTest` (in spring-runtime) — verify the rule it encodes is still the rule.
- Any new `Provider` SPI — verify `ServiceLoader` is the discovery mechanism, never IoC fallback.
