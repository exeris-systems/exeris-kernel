# ADR-085 — Federated Documentation Architecture and Repo-Hygiene Standards (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-085-documentation-architecture-and-repo-hygiene-standards.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-085-documentation-architecture-and-repo-hygiene-standards.md)

ADR-085 is a **platform-scope** decision owned by `exeris-docs`. It binds every Exeris repository,
this one included: documentation stays federated in each repo's `docs/` tree, carries validated
frontmatter, and commits, pull requests, Javadoc, ADRs and agent files follow the standards in
[`exeris-docs/standards/`](https://github.com/exeris-systems/exeris-docs/tree/main/standards).
Structure is gated in CI; prose is reviewed.

## Why this stub exists

The obligations land in files at this repository's root — `AGENTS.md`, `CONTRIBUTING.md`,
`CHANGELOG.md`, the ADR filenames under `docs/adr/` — but the decision behind them is not written
here. A kernel reviewer reading `docs/adr/` should find ADR-085 without needing to know which
repository owns it. ADR-085's Engineering Protocol item 1 asks for this stub by name.

## What is adopted here, and what is not

**Adopted (2026-09-05):**

- **§I.29 — agent files.** [`AGENTS.md`](../../AGENTS.md) is the canonical agent entry point and
  [`.agents/`](../../.agents) is the canonical semantic source: policies, references, skills, role
  profiles and workflows. `.claude/` holds generated adapters carrying a do-not-edit marker, plus
  provider-owned configuration; `CLAUDE.md` is a pointer. The schema is
  [`agents-md-schema.md`](https://github.com/exeris-systems/exeris-docs/blob/main/standards/agents-md-schema.md).
- **§I.30 and §K — AI provenance and contributor terms.**
  [`CONTRIBUTING.md`](../../CONTRIBUTING.md) §"Licence, contributor terms and provenance" states the
  licence, the `Signed-off-by` requirement and the AI-provenance rules, and links
  [`ai-provenance.md`](https://github.com/exeris-systems/exeris-docs/blob/main/standards/ai-provenance.md).
  §K.35 originally read "No CLA"; that sentence was withdrawn on 2026-09-05 because contributor
  licensing is a commercial decision owned elsewhere, not a documentation-ADR decision. This
  repository asks for both a sign-off and an agreement, and says why.

**Not yet adopted — tracked as `[DOC DEBT]`:**

- **§B.7 frontmatter** on the files under `docs/`. None of them carry it today; the scripted
  backfill ADR-085 calls for has not run here.
- **§C.11 reusable workflows.** This repository does not yet call `docs-lint`, `commit-lint`,
  `pr-body-check` or `javadoc-gate` from `exeris-systems/.github`, so none of the `[L1]` gates named
  in the standards runs on a kernel pull request — including `agents_file_check.py`, the gate for
  the agent files this stub records as adopted.
- **§E.16 pull-request template**, **§F.21 Javadoc gates** on the published modules, and
  **§H.27 CHANGELOG `Breaking` sections**.

## When to consult ADR-085 from the kernel

- Any change to `AGENTS.md`, `.agents/**` or a provider directory — the schema's hard rules decide
  where a rule may be authored, and §I.29 forbids `.claude/` becoming a second source.
- Any new document under `docs/` — filename patterns (§G.22), the registry-row-first rule (§G.23)
  and the frontmatter schema (§B.7) all apply, whether or not a gate is watching yet.
- Any cross-repo link. §A.2 as amended on 2026-09-05: a cross-repo reference is an absolute
  `https://github.com/exeris-systems/<repo>/blob/<branch>/<path>` URL naming the branch. A
  sibling-layout path such as `../../exeris-docs/...` resolves only in a full workspace checkout and
  is dead on github.com.
- Any public document that would link into an enterprise-private repository — §A.3 and §G.24 make
  ADR-020's rule machine-checked.
